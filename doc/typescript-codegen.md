# TypeScript codegen from PHP DTOs

The bundle can emit a `.d.ts` file containing one `interface` per configured DTO, plus a `ResourceTypes` map and a `ResourceName` union. Useful if you want the *single source of truth* to stay in PHP while still getting full TypeScript autocomplete in your React-admin app.

## Generate

```bash
# Stdout
php bin/console react-admin-api:dump-typescript

# To a file (recommended)
php bin/console react-admin-api:dump-typescript --output=assets/generated/types.ts
```

## Example output

For a `users` resource backed by `App\Admin\Dto\UserDto`:

```ts
/**
 * Auto-generated by react-admin-api:dump-typescript.
 * Do not edit by hand; rerun the command to refresh.
 */

export interface UserDto {
    id?: number | null;
    email: string;
    name: string;
    /** Server-managed timestamp */
    createdAt: string;
}

export interface ResourceTypes {
    'users': UserDto;
}

export type ResourceName = keyof ResourceTypes;
```

## Conventions

- Nullable PHP types (`?int`, `?string`, …) become optional TypeScript fields (`field?: type | null`).
- `\DateTimeImmutable` / `\DateTime` / `\DateTimeInterface` are emitted as `string` (the bundle already serialises them as ISO 8601 in the response envelope).
- `array` and `mixed` default to `unknown[]` / `unknown`. Override by exposing a richer typed property and decorating it with `#[ApiProperty(description: '…')]` for self-documentation.
- Class types other than `DateTime*` fall back to `Record<string, unknown>`. For relations, project the relevant fields into the DTO explicitly rather than embedding entities.
- `#[ApiProperty(description: '…')]` becomes a JSDoc `/** … */` block above the field so IDEs pick it up.

## Re-run as part of the asset build

Recommended `package.json` script:

```json
"scripts": {
    "codegen": "cd .. && php bin/console react-admin-api:dump-typescript --output=src/generated/types.ts",
    "prebuild": "npm run codegen"
}
```
